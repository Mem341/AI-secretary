# AI-secretary

Особистий Telegram-бот «AI-секретар» для одного керівника: створює зустрічі в Google Calendar з тексту,
голосового, пересланої переписки чи скріншота, розсилає інвайти, бачить зміни в календарі через push від Google.

**Бот відповідає лише одній людині** — власнику з `OWNER_TELEGRAM_ID`. Повідомлення й кнопки від будь-кого
іншого ігноруються без відповіді: сторонній навіть не дізнається, що бот працює.

## Розгортання на Vercel

Найпростіше — попросити агента Claude Code (з підключеним Vercel MCP): «розгорни бота на Vercel».
Інструкція для агента — `.claude/skills/deploy-vercel/SKILL.md`: там перелік того, що він у вас спитає
(токен бота, ваш Telegram ID, ключі Google/OpenRouter/ElevenLabs), і всі кроки до перевірки через `/api/health`.

Коротко, що знадобиться від вас:

1. Токен бота від @BotFather.
2. Ваш **числовий** Telegram ID — напишіть @userinfobot.
3. Google OAuth Client ID/Secret (Google Cloud Console, агент підкаже кроки).
4. Ключі OpenRouter і ElevenLabs.

## Що вміє (етап 1)

- Онбординг: профіль (ПІБ, посада, телефон, тривалість і формат зустрічі за замовчуванням, адреса) і підключення
  Google Calendar через OAuth.
- Картка зустрічі з тексту, голосового, пересланої переписки (серія збирається 15 с) або скріншота; правки
  звичайним текстом, уточнювальне питання при низькій впевненості, 3 вільні слоти, попередження про перетини й
  відсутні email, кнопка «Створити без них».
- «Створити» → подія в Google Calendar з `sendUpdates=all` (інвайти на пошту), гості можуть редагувати, Google Meet.
- Push від Google: бот бачить і події, створені вручну в календарі.
- Адресна книга: імена й email учасників запамʼятовуються, далі достатньо імені (`/contacts`, `/contact`).
- `/settings`, `/cancel`, `/errors` (останні помилки; про кожну помилку бот пише й сам).

Етапи 2 (нагадування за 30 хв, перенесення/скасування, `/today`, `/week`) і 3 (записи, транскрибація, підсумки)
— далі.

## Архітектура

```
Telegram ──webhook──▶ /api/telegram ────┐
Google   ──push────▶ /api/gcal-push ────┤          ┌──▶ Google Calendar API
Браузер  ──OAuth───▶ /api/oauth/* ──────┼─ Vercel ─┼──▶ OpenRouter (LLM)
Vercel Cron (щодня) ▶ /api/cron/daily ──┤ Functions└──▶ ElevenLabs Scribe (голос)
Перевірка ─────────▶ /api/health ───────┘     │
                                          Neon Postgres
```

- Функції відповідають Telegram одразу; важка робота (LLM, транскрибація, синхронізація) виконується після
  відповіді через `waitUntil`, до 3 спроб. Остаточний збій пишеться в `errors` і приходить власнику в Telegram.
- Google push: `events.watch` на `/api/gcal-push` із секретним токеном каналу → `events.list` із `syncToken`.
  Щоденний cron продовжує канал і робить повну синхронізацію на 30 днів як страховку (на тарифі Hobby cron
  дозволено раз на добу).
- Схема БД створюється автоматично при першому запиті (`src/db/schema.ts`).
- Безпека: перевірка власника на кожному вході, секрет вебхука Telegram, токен каналу Google, `CRON_SECRET`,
  підписаний `state` в OAuth, токени Google шифруються AES-256-GCM.

### Навіщо база даних

Функції Vercel нічого не памʼятають між запитами, тому без сховища бот не зможе працювати правильно:

| Що зберігається | Навіщо |
| --- | --- |
| Токени Google (зашифровані) | створювати події від вашого імені без повторного входу |
| Картка зустрічі до «Створити» | кнопки «Змінити / Створити» натискаються в іншому запиті |
| Серія пересланих повідомлень | зібрати переписку в одну картку |
| Стан push-каналу і `syncToken` | отримувати від Google лише зміни і продовжувати підписку |
| Дзеркало календаря | вільні слоти і попередження про перетини; нагадування за 30 хв на етапі 2 |
| Адресна книга, помилки | email за іменем, діагностика |

Neon Free (0.5 GB) для однієї людини вистачить з великим запасом.
